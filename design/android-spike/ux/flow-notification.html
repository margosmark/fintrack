Steps

    ↳ = branch / variant. The pill at the bottom of each frame is Android system back — press it to test back behavior from every depth.

    Current step

    Capability 2 earns itself only if…

    • An existing server alert event can drive the notification — no new alert system invented for the mockup (docs/49 Q2, audit owed).
    • OS-surface copy stays generic in every run: zero amounts, merchants, tickers or account names, masked or not.
    • Tap → auth → revalidated deep link reaches the intended record ≥95% of test deliveries on the supported device set (docs/49 threshold).
    • Every fallback (stale link, expired session, permission denied) has an in-app frame here — none is a silent failure.
    • Opening a notification never mutates alert state; no faux “Resolve” action exists.

    If the alert-source audit finds no server event that safely supports this journey, capability 2 fails the gate before any platform question — the mockup cannot manufacture the backend.
