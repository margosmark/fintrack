Steps

    ↳ = branch / variant. The pill at the bottom of each frame is Android system back — press it to test back behavior, including at the root.

    Current step

    Capability 1 earns itself only if…

    • Re-entry to a valid session is measurably faster than the web sign-in path, without teaching users that biometrics = authentication.
    • Cancel and expired-session both land on sign-in with a preserved (internal) destination — zero dead ends.
    • Re-entry default is masked; reveal never survives backgrounding; recents preview is generic in every run.
    • Server auth stays authoritative: no frame offers fingerprint as recovery.
    • 44px floor on every control; state carried by label + icon, not color alone.

    If these hold on-device but the PWA can meet them too (WebAuthn re-auth, screenshot/recents limits aside), capability 1 has not earned a native client — that differential is the spike's measurement.
