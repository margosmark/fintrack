Android capability spike · interactive UX mockups

Bounded spike deliverable (option 2): validate whether Android-native capabilities justify a Kotlin/Compose client — not a full app build. Grounded in docs/48-android-companion-ux.md and docs/49-android-companion-recommendation.md; visual direction from design/android-material/. All names, balances, times and alerts in frames are illustrative. No production write path exists in any frame — every screen is read-only.

Provenance states — the spec every screen must carry

A number without provenance fails this deliverable. Each state below is a visible marker (chip or banner) on every value-bearing screen. Freshness (server recency) and tenant mode (demo read-only) are orthogonal: a demo screen can be fresh, stale or offline — it shows both markers.

Fresh · server 10:42 AM

Server answered this session. The timestamp is the server's own response time, not the client clock.

Stale · last server update 10:42 AM · 2h 27m ago

Refresh attempted and failed (or data aged past threshold). Values remain visible but are never styled as current; copy names the failure and the last successful time, and offers Retry.

Banner: “Couldn't update. Showing data from 10:42 AM.”
Offline snapshot · saved Oct 26, 9:40 PM

Opt-in, read-only snapshot of a previous server response. Persistent banner + per-card chip; no refresh, no quotes, no writes, no client math. Cleared on logout / identity change / policy expiry.

Banner: “Offline · snapshot saved Oct 26, 9:40 PM · read-only”
Snapshot expired

Past the snapshot time-to-live, or snapshot absent. Values are withheld — labels and layout stay, numbers do not render. Distinguished from zero, unavailable and hidden.

“Values are hidden because this snapshot is older than 24 h. Reconnect to view current values.”
Demo · read-only

Tenant mode marker, persistent on every demo surface. Writes are refused by the server (demo_account_restricted) — no frame implies a demo mutation can persist.

Banner: “Demo · read only — explore sample data. Changes are disabled.”
Values hidden

Display mask state. Masked values never appear in app-switcher previews or OS notification surfaces, regardless of in-app reveal state. Mask hides display only — not network or stored data.

Amounts render as ••••••••; accessibility labels announce “value hidden”.
This item is no longer available

Deep-link target deleted, expired or outside the tenant. Generic state + safe back — never another record, never confirmation that a foreign-tenant ID exists.

Notification → deleted alert → this state, then Back → Alerts.

Capability scorecard — what each mockup must prove to earn itself

Candidate capabilityMockup coverageSpike must demonstrate (pass condition)Status
1 · Biometric / device-lock re-entry flow-reentry.html Re-entry without server re-auth when the session is valid; cancel and expired-session both land on sign-in with the intended destination preserved internally; masked default; zero values in recents preview; users don't read the prompt as account recovery. Concept — to validate
2 · Reliable local notifications flow-notification.html An existing server alert event can drive a generic notification (no amount/merchant/security/account on the OS surface), tap → auth → revalidated deep link reaches the intended record ≥95% of test deliveries, and every unsupported state has an in-app fallback (docs/49). Concept — alert-source audit owed
3 · Offline-safe read-only snapshot flow-offline.html Snapshot is a verbatim server response (no client math), every frame carries its age, expiry withholds values rather than showing them, logout/identity change clears it, and revocation is demonstrable. Omit the feature entirely if private invalidation can't be proven (docs/49). Concept — threat model owed
4 · Android-native navigation & system back All three flows — the gesture pill at the bottom of each frame Back walks detail → list → home preserving scroll/selection; back from a notification destination never exits to an unrelated tenant screen; back at root shows an honest “would leave the app” state instead of navigating nowhere. V1 behavior — expected baseline
5 · Controlled local private storage flow-offline.html — storage facts panel Stored fields enumerated and minimal, encrypted at rest under a documented key/ownership model, cleared on logout/identity change/expiry, and revocable by the user. If the model can't be audited, the snapshot stays out of scope. Concept — storage design owed
