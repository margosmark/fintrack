Steps

    ↳ = branch / variant. The pill at the bottom of each frame is Android system back — press it to test back behavior, including from offline detail (o8 → o3).

    Current step

    Capabilities 3 + 5 earn themselves only if…

    • The snapshot is a stored verbatim server response — a storage dump shows server fields, no derived values (no client math, ever).
    • Every value-bearing frame carries banner + chip with the snapshot's save time; the expired frame (o4) contains zero currency strings.
    • Logout / identity change / TTL each provably wipe the data — including offline logout, with no network round-trip.
    • Revocation is a user control (o9), not just a policy sentence; deleting it lands the user in o5, not a stale render.
    • If the threat model can't back the key/ownership line, the capability is dropped and o5 ships — dropping it is a pass, not a failure.

    The PWA comparison to beat: a service-worker cache can store the same bytes, but scope, TTL and identity-scoped wipe are far easier to audit natively — that auditability gap is what this flow measures (docs/49 platform matrix).
