# Dividend suggestions and shared valuation read-path plan

## Context

The existing `GET /trades/dividend-suggestions` reads committed trades, then waits for yfinance once per distinct open security. `compute_positions` also reaches price and FX fetch seams while building a read response, and performs per-held-security/per-currency reads. This plan pins a bounded, cache-first read contract without caching financial totals. It preserves the financial calculation and all existing tenant, privacy, and freshness rules.

Baseline evidence is measured on the current implementation commit before optimization. Preserve historical measurements in docs/34; this document records the behavioral/performance contract, not a claim that any threshold is already achieved.

## Dividend history contract

### Persistence

If the existing price/history tables cannot represent provider dividend events, add tenant-scoped `dividend_history` rows. Columns: `id` integer primary key; `user_id` integer FK to `users.id` (indexed by the leading prefix of composite indexes); `security_id` integer FK to `securities.id`; `ex_date` date; `amount` `Numeric(20,8)` (positive per-share amount in the security listing currency); `provider_order` integer (preserves provider response order and duplicate dates); `source` VARCHAR/StrEnum restricted to `yfinance`; timestamps from `TimestampMixin`. Unique key `(user_id, security_id, source, provider_order)` preserves every raw provider entry, including duplicate dates. Add an index on `(user_id, security_id, ex_date)`. Add refresh metadata with `(user_id, security_id)` identity and a worker index on `(state,last_attempt_at)`, `last_success_at` nullable timestamp, `last_attempt_at` nullable timestamp, `state` enum `pending | refreshing | available | empty | unavailable`, and bounded `error_code` nullable string. A successful non-empty fetch atomically replaces that tenant/security's yfinance events and sets `available`; a successful empty response clears old events and sets `empty`; errors/timeouts or malformed/non-finite/non-positive provider data retain events and `last_success_at`, update only attempt/state/error, and must not publish a partial or false-empty result. No financial aggregate or suggestion result is persisted. Migration is additive and downgrade removes only the new objects.

### Fetch and refresh

All provider access remains through `services/market_data.fetch_dividend_history`. Its result must distinguish successful empty history from unavailable (`[]` vs `None`). Refresh age is 24 hours from `last_success_at`; an unavailable result does not reset this clock. Refresh work is finite-deadline, bounded-concurrency and single-flight per `(user_id, security_id)`, coalesced on repeated misses, and uses a lifecycle-owned runner with its own short-lived sessions. The in-process worker polls every 2 seconds, executes at most 8 jobs serially per tick (global concurrency 1), and uses the 5-second market-data deadline. Pending rows survive restart; `refreshing` rows older than five minutes are re-queued by the worker after a crash. Workers atomically claim each `(user_id, security_id)` through a row lock and publish `refreshing` before network I/O, preventing duplicate provider calls across processes. No request `Session` remains open during provider wait. A refresh rechecks that the security is owned by the tenant and that the tenant's current privacy mode permits egress immediately before the provider call. Privacy mode and dead-symbol policy block provider access; no status update may imply a successful empty history in those cases.

The read endpoint never waits for provider work. It loads persisted raw events and current committed/manual trades, recomputes all suggestions per read, and queues due refreshes. Missing history is not interpreted as a no-dividend result. Keep the JSON body `DividendSuggestion[]` byte-compatible. Add `X-Dividend-History-State` response header containing JSON `{"pending":<int>,"unavailable":<int>,"empty":<int>,"stale":<int>,"as_of":"<UTC timestamp>|null"}`; `as_of` is the oldest successful refresh timestamp represented in the current response scope; all counts are per distinct tenant/security source, not per account holding. `stale` counts only a prior success older than 24 hours; a never-successful history is pending/unavailable, not stale. `empty` explicitly distinguishes successful-empty provider history from unavailable/missing data. Header values are bounded and do not contain symbols or user data. The frontend reads the header and displays a visible pending/unavailable notice even when the body is empty; stale cached suggestions are labeled with refresh age/state. Existing account filter and tenant isolation remain unchanged.

### Financial parity

Use committed/manual trades only; preserve account filter, current-open positions (`net quantity > 0`), same-day trades included in shares held, Decimal arithmetic and existing 0.01 output quantization, currency, output order, and suppression for recorded `dividend`, `distribution`, and `return_of_capital` trades on the same account/security/date. Current committed trades are reread every request, so edits/import commits/recorded income immediately affect suggestions without invalidation. Keep once-per-symbol fetch deduplication for explicit refresh paths. Any timeline algorithm change requires fixed-provider parity and synthetic 1k/10k/large trade tests proving improved work/scaling, including unsorted trades, multiple same-day trades, and duplicate/unsorted provider dates.

## Shared valuation contract

`services/valuation.compute_positions` remains the single authoritative valuation pass for all existing callers. Batch latest usable price rows, bounded spark/previous-close history, FX rates by distinct currency pair, securities, and persisted ACB pools before rendering positions. Warm SQL statement count must not grow linearly with held securities or repeated account/security pairs; pin fixtures holding 1, 10, and 50 securities and repeated pairs. Preserve account_id and account_ids allowlists, committed staging predicate, registered-account replay, transfer/action semantics, and household privacy.

The read path may read cached data and schedule eligible background refreshes but MUST NOT wait on price or FX providers. Existing automatic portfolio market-hours refresh, explicit `POST /portfolio/refresh`, and explicit `POST /securities/{id}/refresh` remain available with existing semantics, including manual-price wins, dead-symbol handling, and discoverability to other shared service callers. Do not remove ensure/fetch behavior from unrelated account, tax, exposure, or projection callers without a separately approved change.

Keep `price_date`, source, age, stale iff age > 7 days, unknown price/FX/book-cost as `None`, manual overrides, sparkline last-30 ordering, previous-close strictly before selected price, header=sum(rows), reporting currency, and per-date tax FX semantics. Bound history query to enough rows per held security for spark and previous-close (30 newest closes plus the immediately preceding close), excluding future dates; do not load all production price history. Money/quantity/rate math remains Decimal. Existing explicitly documented percentage display calculations are not changed by this work.
