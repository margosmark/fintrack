Imports

Upload bank statements safely: staged, reviewed, then committed.

  1. Upload a statement

    Head to Imports → Upload a statement and drop in your bank or brokerage CSV. Map the columns once (date, description, amount); the mapping is remembered per institution next time.

  2. Review the staging batch

    Imports land in a staging batch first — nothing counts toward balances, budgets, or reports until you commit. Review the parsed rows, fix anything odd, then commit the batch to make it official.

  3. Duplicates are blocked

    Re-importing the same file will not create duplicates: dedup spans pending and committed batches. If a file is rejected, the error names the exact row and reason (bad date, bad amount, unknown column) so you can fix and retry.

  4. Move over a YNAB budget

    Coming from YNAB? The Migrate from YNAB guide walks through both exports (a full-budget JSON straight from YNAB's API, or one account's register CSV) and lists exactly what carries over and what does not. Short version: the preview maps every account, category, group tag, and target, and lists each row it cannot import with its row number and reason — nothing is dropped silently. Accounts, categories, and tags are matched by name, so running the import a second time adds nothing, and every transaction lands in a review batch you commit yourself.
