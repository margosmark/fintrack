Brokerage imports

Where each broker keeps its activity export, which file to take, and exactly what the importer refuses.

  1. Export activity, not positions

    Every one of these profiles wants a transaction file — one row per trade, dividend, deposit or fee — not a holdings snapshot. Positions files carry a balance with no history, so there is nothing to reconcile against. Take the widest date range you have not imported yet: re-reading the same file a second time stages nothing new, because duplicates are decided on account, security, date, action, quantity and price.

  2. Pick the broker before you upload

    Imports → choose an investment account → Import as “Investment trades” → Broker export. Leaving it on auto-detect matches the file header against every profile; choosing the institution pins the parser and refuses a file that does not match that broker's export instead of force-fitting it. Either way you get the same staged batch: review the rows, then commit — nothing counts toward balances or reports until you do.

  3. Questrade

    Where: Reports → Account Activity → all activity types → Download (CSV). Take the whole activity list, not a trades-only slice, so deposits and dividends land in the same file. Quirk: the export carries both Transaction Date and Settlement Date; only the trade date is used, and the settlement column is reported as read-and-ignored rather than silently feeding a calculation.

  4. Wealthsimple

    Where: the account's Activity list → Download activities → CSV. Quirk: express orders are labelled “Buy - Express” / “Sell - Express” in the file. Those labels are recognized, along with DRIP sub-types; anything Wealthsimple writes that is not in the profile's vocabulary comes back as a listed row with its line number rather than vanishing.

  5. Interactive Brokers (and IBKR Canada)

    Where: Performance & Reports → Flex Queries → Activity Flex Query, and set Format = CSV — the two supported layouts are the flat CSV export and the sectioned Activity Statement, which is read block by block. Quirk: every row states its own CurrencyPrimary, so one file can hold CAD and USD rows side by side and each is treated in its own currency. Canadian accounts export the identical layout; only CurrencyPrimary reads CAD. Leave the Corporate Actions section out of the routine query — see “What the importer refuses” below.

  6. Fidelity (US)

    Where: Accounts & Trade → Activity & Orders → Download CSV. Quirk: the file states no currency at all, so every row is USD no matter which account you import it into — including a CAD account, where the conversion then runs through your cached exchange rates. Commission and fees arrive in two separate columns and are added together.

  7. TD Direct Investing

    Where: WebBroker → the account → Activity → Export (CSV). Quirk: the CAD and USD sides of an account are separate exports, so export both and import each against its matching account — nothing here merges them. Quantity notation such as 1E+1 is read as 10, and quoted descriptions that wrap across two lines stay one row.

  8. RBC Direct Investing

    Where: My Portfolio → Account Activity → Download (CSV). Quirk: the export has no commission column, so trades import with commission 0.00. That is stated as a notice on the preview — check the rows against your statement rather than assuming the broker charged nothing.

  9. National Bank Direct Brokerage

    Where: Account → Transaction History → Download (CSV). Quirk: NBDB publishes the same file in English or French. The French columns (Achat, Vente, Dividende, Dépôt, Quantité, Prix, Devise) and the semicolon separators are read as-is, and rows with no currency take the currency of the account you import into.

  10. What the importer refuses

    Two things stop the whole file rather than a row. A date or a number that cannot be read: importing the rows around it would leave a history that looks complete and is not, so the file is refused with the line number and the formats that would work. A split, merger or reorganization: no supported export states the share count an adjustment needs, so the row is refused with a pointer to entering it by hand instead of being turned into a wrong position. Everything else that cannot become a trade is listed with its line number, the raw activity word and the institution — never dropped in silence.

What is never guessed

SituationWhat you get
A date in an order the profile does not accept (05/06/2026)The row is listed with its line number and the date formats that would work — never a silently swapped day and month. No Canadian profile reads a slash date at all, because the ambiguity cannot be resolved from the data.
A quantity, price or amount that is not a numberThe whole file is refused with the line number, instead of importing the rows around it.
A split, merger or reorganization in the exportThe whole file is refused with the line number and the activity word. Add the adjustment by hand on the Investments page, then re-import with that activity excluded.
An activity word the broker uses but the profile does notA listed row carrying its line number, the raw word and the institution. It is never turned into a guess.
A currency the file does not stateA per-broker rule: Fidelity rows are always USD; NBDB and RBC blank cells take the account's currency; every other profile requires the cell to be a real three-letter code.
The same file imported twiceThe second run stages the rows as duplicates and imports nothing new. Duplicates stay in the batch for you to review and can be included one by one.
